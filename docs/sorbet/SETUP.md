# Sorbet Setup Guide

## Installation

Sorbet has been integrated into this project with all necessary configuration files in the repository.

### Initial Setup (First Time)

1. **Install dependencies**:
   ```bash
   bundle install
   ```

2. **Initialize Tapioca** (creates bin/tapioca wrapper):
   ```bash
   bin/tapioca init
   ```

3. **Generate RBI files**:
   ```bash
   # Generate RBIs for all gems
   bin/tapioca gem --all

   # Generate RBIs for Rails DSLs (models, controllers, etc.)
   bin/tapioca dsl
   ```

4. **Verify Sorbet is working**:
   ```bash
   bin/sorbet
   ```

   You should see: "No errors! Great job." (or type errors if files already have type signatures).

## Daily Workflow

### After `bundle install` or `bundle update`

Whenever gems are added, removed, or updated:

```bash
bin/tapioca gem --all
```

This regenerates the RBI files in `sorbet/rbi/gems/` to match your current Gemfile.lock.

### After modifying models or DSL code

When you add/remove models, change associations, add enums, etc.:

```bash
bin/tapioca dsl
```

This regenerates the RBI files in `sorbet/rbi/dsl/` to reflect your current model definitions.

### Before committing changes

Always run Sorbet to check for type errors:

```bash
bin/sorbet
```

Or run the full check suite (includes Sorbet):

```bash
bin/check
```

### When adding type signatures to a file

1. Add the strictness sigil at the top of the file:
   ```ruby
   # typed: true
   # frozen_string_literal: true
   ```

2. Add `extend T::Sig` to the class or module:
   ```ruby
   class MyClass
     extend T::Sig
     # ...
   end
   ```

3. Add signatures to methods:
   ```ruby
   sig { params(name: String).returns(String) }
   def greet(name)
     "Hello, #{name}"
   end
   ```

4. Run Sorbet to verify:
   ```bash
   bin/sorbet app/models/my_class.rb
   ```

See [TYPING_PATTERNS.md](TYPING_PATTERNS.md) for comprehensive examples.

## IDE Integration

### VS Code

1. Install the Sorbet extension:
   - Extension ID: `sorbet.sorbet-vscode-extension`
   - Name: "Sorbet LSP"

2. Add to `.vscode/settings.json`:
   ```json
   {
     "sorbet.enabled": true,
     "sorbet.commandPath": "bin/sorbet"
   }
   ```

### RubyMine

1. Go to **Preferences > Languages & Frameworks > Ruby > Sorbet**
2. Enable "Use Sorbet type checker"
3. Set Sorbet executable to `bin/sorbet`

### Vim/Neovim

Use the Language Server Protocol (LSP) client with sorbet-lsp:

```vim
" Example for coc.nvim
{
  "languageserver": {
    "sorbet": {
      "command": "sorbet",
      "args": ["tc", "--lsp"],
      "filetypes": ["ruby"],
      "rootPatterns": ["sorbet/config"]
    }
  }
}
```

```
├── rbi/

```

## Rake Tasks

```bash
# Check if RBI files are up to date
bin/rake sorbet:verify_rbis

# Regenerate all RBI files
bin/rake sorbet:regenerate

# Run Sorbet type checker
bin/rake sorbet:check
```

## Strictness Levels

Files can have different strictness levels via the `# typed:` sigil:

- **`# typed: false`** - Opt out of type checking (for legacy code)
- **`# typed: true`** - Basic type checking (most application code)
- **`# typed: strict`** - All methods must have signatures (critical code)
- **`# typed: strong`** - No `T.untyped` allowed (library code)

Start with `typed: false`, then gradually increase to `typed: true` as you add signatures.

## Common Commands Reference

```bash
# Type check everything
bin/sorbet

# Type check specific file
bin/sorbet app/models/book.rb

# Type check with suggested strictness levels
bin/sorbet --suggest-typed

# Show autocorrect suggestions
bin/sorbet -a

# Generate RBIs for all gems
bin/tapioca gem --all

# Generate RBIs for DSLs
bin/tapioca dsl

# Full check (includes Sorbet)
bin/check
```
