# RBI Maintenance Guide

## What are RBI Files?

RBI (Ruby Interface) files are type signature files that describe the structure of Ruby code without containing implementation. They allow Sorbet to understand code that isn't directly type-checked.

There are three types of RBI files in this project:

1. **Gem RBIs** (`sorbet/rbi/gems/`) - Auto-generated type definitions for gems
2. **DSL RBIs** (`sorbet/rbi/dsl/`) - Auto-generated type definitions for Rails DSLs (ActiveRecord, etc.)
3. **Manual RBIs** (`sorbet/rbi/manual/`) - Hand-written type definitions for gems without type support

## Directory Structure

```
sorbet/rbi/
├── gems/                    # Auto-generated (DO NOT EDIT)
│   ├── rails@8.0.1.rbi
│   ├── graphql@2.3.0.rbi
│   └── ...
├── dsl/                     # Auto-generated (DO NOT EDIT)
│   ├── book.rbi
│   ├── register.rbi
│   └── ...
├── todo.rbi                 # Auto-generated by Sorbet (DO NOT COMMIT)
└── manual/                  # Hand-written (EDIT AS NEEDED)
    ├── closure_tree.rbi
    ├── acts_as_list.rbi
    ├── currencyable.rbi
    ├── money_rails.rbi
    ├── montrose.rbi
    ├── pundit.rbi
    └── graphql_extensions.rbi
```

## When to Regenerate Auto-Generated RBIs

### Gem RBIs (`sorbet/rbi/gems/`)

Regenerate whenever you:
- Add a new gem to Gemfile
- Remove a gem from Gemfile
- Update gem versions with `bundle update`

```bash
bin/tapioca gem --all
```

This command:
- Reads your `Gemfile.lock`
- Generates RBI files for each gem
- Removes RBI files for gems no longer in use
- Takes 30-60 seconds typically

### DSL RBIs (`sorbet/rbi/dsl/`)

Regenerate whenever you:
- Add/remove a model, controller, or mailer
- Add/remove associations (`belongs_to`, `has_many`, etc.)
- Add/remove scopes
- Add/remove enums
- Add/remove validations
- Modify GraphQL types or mutations

```bash
bin/tapioca dsl
```

This command:
- Loads your Rails application
- Inspects all classes for DSL usage
- Generates type signatures for dynamically generated methods
- Takes 10-20 seconds typically

### Both at Once

```bash
bin/tapioca gem --all && bin/tapioca dsl
```

Or use the rake task:

```bash
bin/rake sorbet:regenerate
```

## When to Create Manual RBIs

Create manual RBIs when:

1. **A gem has no type definitions** and Tapioca can't generate them automatically
2. **A gem uses metaprogramming** that Tapioca can't analyze
3. **You need custom type signatures** for gem methods
4. **Your own code uses metaprogramming** (like the `Currencyable` concern)

### Example: closure_tree

The `closure_tree` gem uses metaprogramming to add methods to models. Tapioca can't automatically detect these, so we created `sorbet/rbi/manual/closure_tree.rbi`:

```ruby
# typed: strong
module ClosureTree
  module Model
    sig { returns(T.nilable(T.untyped)) }
    def parent; end

    sig { returns(ActiveRecord::Relation) }
    def children; end

    # ... more methods
  end
end
```

## Manual RBI Maintenance Workflow

### Adding a New Manual RBI

1. **Identify the need**: You get a Sorbet error like "Method `parent` does not exist on `Register`"

2. **Create the RBI file**:
   ```bash
   touch sorbet/rbi/manual/my_gem.rbi
   ```

3. **Write type signatures**:
   ```ruby
   # typed: strong
   # frozen_string_literal: true

   module MyGem
     sig { returns(String) }
     def some_method; end
   end
   ```

4. **Test it**:
   ```bash
   bin/sorbet app/models/register.rb
   ```

5. **Commit the file**:
   ```bash
   git add sorbet/rbi/manual/my_gem.rbi
   git commit -m "Add Sorbet RBI for my_gem"
   ```

### Updating an Existing Manual RBI

When a gem's API changes:

1. **Read the gem's documentation** to understand the new API
2. **Edit the RBI file** to add/remove/modify signatures
3. **Test with Sorbet**:
   ```bash
   bin/sorbet
   ```
4. **Commit the changes**

### Example: Adding a Method to Currencyable

If you add a new method to the `Currencyable` concern:

```ruby
# app/models/concerns/currencyable.rb
def has_currency(attribute_name, optional: false)
  # ... generates currency_code= method
  # ... generates currency method
  # ... generates currency= method

  # NEW: generates currency_symbol method
  define_method("#{attribute_name}_symbol") do
    send(attribute_name).symbol
  end
end
```

Update the manual RBI:

```ruby
# sorbet/rbi/manual/currencyable.rbi
class Book
  sig { returns(String) }
  def default_currency_symbol; end
end

class Register
  sig { returns(String) }
  def currency_symbol; end
end
```

## Troubleshooting RBI Issues

### "Unable to resolve constant"

**Cause**: Sorbet can't find a class or module.

**Solution**: Check if the gem is in `Gemfile.lock`, then regenerate:
```bash
bin/tapioca gem --all
```

### "Method does not exist"

**Cause**:
- DSL-generated method not in RBI
- Manual RBI missing a method signature

**Solution 1** (DSL method): Regenerate DSL RBIs:
```bash
bin/tapioca dsl
```

**Solution 2** (Gem method): Add to manual RBI or regenerate gem RBIs:
```bash
bin/tapioca gem --all
```

### "Conflicting definitions"

**Cause**: Same method defined in multiple RBI files.

**Solution**: Remove duplicate from manual RBI (let Tapioca handle it).

### "Expected type X, got type Y"

**Cause**: RBI signature doesn't match actual return type.

**Solution**: Update the RBI signature to match reality:
```ruby
# If you have this:
sig { returns(String) }
def currency; end

# But it actually returns Money::Currency, change to:
sig { returns(Money::Currency) }
def currency; end
```

Types for GraphQL-related methods used in this application (field definitions, mutations, etc.).

## Best Practices

### DO ✅

- **Regenerate RBIs after bundle operations**: `bin/tapioca gem --all`
- **Regenerate DSL RBIs after model changes**: `bin/tapioca dsl`
- **Commit manual RBIs to git**: They're part of the codebase
- **Use `typed: strong` in manual RBIs**: Manual RBIs should be fully typed
- **Add comments to complex signatures**: Explain why something is typed a certain way
- **Version control**: Commit RBI changes with related code changes

### DON'T ❌

- **Don't edit auto-generated RBIs**: They'll be overwritten on regeneration
- **Don't commit `todo.rbi`**: It's regenerated by Sorbet and is machine-specific
- **Don't use `T.untyped` in manual RBIs**: Be specific about types
- **Don't duplicate Tapioca signatures**: If Tapioca can generate it, let it
- **Don't forget to regenerate**: Stale RBIs cause false errors

## Verification

To verify RBIs are up to date (useful in CI):

```bash
bin/rake sorbet:verify_rbis
```

This will:
1. Regenerate all RBIs
2. Check if any files changed
3. Fail if RBIs are out of date
4. Show which files need regeneration

## Git Integration

### What to Commit

✅ **DO commit**:
- `sorbet/rbi/gems/**/*.rbi` (gem RBIs)
- `sorbet/rbi/dsl/**/*.rbi` (DSL RBIs)
- `sorbet/rbi/manual/**/*.rbi` (manual RBIs)

❌ **DON'T commit**:
- `sorbet/rbi/todo.rbi` (machine-specific, regenerated by Sorbet)

### .gitignore

Ensure `.gitignore` includes:

```
# Sorbet
sorbet/rbi/todo.rbi
```

### Handling Merge Conflicts

RBI files can conflict during merges. To resolve:

1. **Accept both changes** (or either)
2. **Regenerate RBIs**:
   ```bash
   bin/tapioca gem --all
   bin/tapioca dsl
   ```
3. **Verify Sorbet is happy**:
   ```bash
   bin/sorbet
   ```
4. **Commit the regenerated files**

Tapioca will regenerate the correct signatures, so manual conflict resolution isn't critical.

## Performance Tips

### Faster DSL Generation

If DSL generation is slow, you can target specific paths:

```bash
# Only regenerate model RBIs
bin/tapioca dsl app/models

# Only regenerate controller RBIs
bin/tapioca dsl app/controllers
```

### Parallel Generation

Tapioca supports parallel generation:

```bash
bin/tapioca gem --all --workers=4
```

### Caching

Tapioca caches gem RBIs. To clear the cache:

```bash
rm -rf tmp/tapioca
bin/tapioca gem --all
```

## Summary

| Action | Command | When |
|--------|---------|------|
| Generate gem RBIs | `bin/tapioca gem --all` | After bundle install/update |
| Generate DSL RBIs | `bin/tapioca dsl` | After model/controller changes |
| Both | `bin/rake sorbet:regenerate` | Anytime you're unsure |
| Verify RBIs | `bin/rake sorbet:verify_rbis` | In CI or before commits |
| Create manual RBI | Create file in `sorbet/rbi/manual/` | For gems without type support |

**Golden Rule**: When in doubt, regenerate both and run Sorbet:

```bash
bin/tapioca gem --all && bin/tapioca dsl && bin/sorbet
```
